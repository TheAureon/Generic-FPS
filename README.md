# Generic FPS

A singleplayer first-person shooter that runs in your web browser. You fight AI bots that see, hear, take cover, retreat, and hunt you around the map.

Built with [Three.js](https://threejs.org/) (3D graphics) and [Vite](https://vitejs.dev/) (development server), in TypeScript. There are no image or audio files: every model is built from simple shapes in code, and every sound is generated by code.

---

## How to play (Mac)

### Quickest: double-click `index.html`

Double-click **`index.html`** in the project folder. It opens in your browser at the title screen. You don't need Terminal or Node.js. (`Play.html` is an identical copy, kept so older links still work.)

`index.html` is the complete game in a single file. If you change `src/config.ts`, either play through the development server below, which shows your changes instantly, or run `npm run build` to rebuild `index.html` and `Play.html`.

### Putting it on a website

Upload **`index.html`** to any web host. It's the whole game in one file, with nothing else needed. When someone opens your site (or the folder you put it in), the game starts.

For **GitHub Pages**, go to the repository's **Settings → Pages**. Under "Build and deployment", choose "Deploy from a branch", pick this branch and the `/ (root)` folder, and save. The site serves `index.html` automatically.

### Development server (to tweak the game)

#### One-time setup

1. **Install Node.js.** Go to <https://nodejs.org>, download the **LTS** installer for macOS, and run it.
2. **Get the code.** Open the **Terminal** app (press Cmd+Space, type *Terminal*, press Enter) and paste:
   ```bash
   cd ~/Desktop
   git clone https://github.com/TheAureon/Generic-FPS.git Generic-FPS
   cd Generic-FPS
   git checkout claude/tender-rubin-0yqqrq
   ```
   If your Mac asks to install "command line developer tools", click **Install**, wait for it to finish, then paste the commands again.
3. **Install the game's libraries:**
   ```bash
   npm install
   ```

#### Every time you want to play

```bash
cd ~/Desktop/Generic-FPS
npm run dev
```

Your browser opens the game automatically. If it doesn't, open <http://localhost:5173/dev.html>.
To stop the server, click the Terminal window and press **Ctrl+C**.

#### Getting updates

```bash
cd ~/Desktop/Generic-FPS
git pull
npm install
```

Chrome is recommended. Safari and Firefox also work.

## Playing

The game opens on the title screen. Click or press any key to reach the main menu, where you can **Play**, read **How to play**, or open **Settings**. Click **Play**, choose your match, and click **Start**. Your choices are remembered for next time.

- **Mode**: Deathmatch or Survival (below)
- **Map**: Foundry (the main arena) or Test Room (small)
- **Difficulty**: Easy, Normal, or Hard. This changes how fast bots react, how accurately they aim, how fast they turn, how long their bursts are, and how aggressive they are.
- **Bots**: 1–10
- **Kill limit** (Deathmatch): 10, 20, or 30

### Game modes

- **Deathmatch**: everyone for themselves, bots included. First to the kill limit wins. If the 10-minute timer runs out first, the most kills wins. Everyone respawns a few seconds after dying.
- **Survival**: waves of bots hunt you. Wave 1 has the number of bots you chose, and each wave adds one (up to 12). Bots get faster and more accurate each wave until wave 6. You have one life, and clearing a wave gives you back 30 health. Your score is how many waves you survive.

When a match ends, the scoreboard shows the result, your kills, deaths, and accuracy, with buttons to play again or return to the main menu.

### On screen

- **Bottom left**: health (turns red when low) and armor
- **Bottom right**: your weapons and ammo
- **Top left**: the minimap. It turns with you (up is the way you're facing) and shows walls, pickups, and enemies you can see or that just fired. A triangle means the enemy is above or below you.
- **Top center**: score, leader, and time left (or wave and enemies left)
- **Top right**: kill feed
- **Middle**: crosshair (spreads out when your shots are less accurate), hit markers (white = hit, yellow = headshot, red = kill), and a red arc pointing toward whoever is shooting you

### Pickups

Walk over a pickup to grab it. Each one comes back 20–30 seconds after it's taken.

- **Health** (white case, red cross): +35 health
- **Armor** (blue vest, on the Foundry roof): +50 armor. Armor soaks up 60% of each hit until it runs out.
- **Ammo** (crate with bullets): two spare magazines for every gun

Hurt bots go for health pickups too.

### Settings

Open **Settings** from the main menu or the pause menu. Changes are saved automatically.

- **Mouse sensitivity**, **Field of view**, **Volume**
- **Screen shake**: on or off
- **Graphics**: Low, Medium, or High. If the game feels choppy, try Medium or Low. Some changes take full effect from the next match.
  - **Low**: no shadows, simpler (cheaper) surface shading, lower resolution, and flat painted textures instead of 3D bricks and concrete panels. Helps most on Retina screens.
  - **Medium**: shadows, faint reflections on metal and armor, and real 3D bricks and concrete panels on the walls.
  - **High**: full resolution, sharper soft-edged shadows, and a glow ("bloom") around lamps, visors, and muzzle flashes.

  The map is detailed on every setting: wooden crates have frames, braces and planks, and the yellow barriers are sloped jersey barriers in sections. On Medium and High the brick walls are built from individual 3D bricks (with mortar between them) and the concrete walls from cast panels with seams and form-tie holes.

  On every setting the map has **baked lighting**: when a map loads, the game works out once how dark each corner is and how much light each wall lamp throws, and paints that onto the surfaces. That looks like many lights but costs almost nothing while playing. Soldiers pick up the color of lamps they walk past the same way, and so does the gun in your hands.

## The soldiers

Bots are low-poly soldiers (helmet with a glowing visor, armored vest, backpack, team-colored shoulder pads) with a real skeleton, drawn as a single mesh so many bots stay cheap. All animation is done in code:

- legs walk or run in the direction they move (including strafing and backing up) while the upper body keeps aiming at you
- both hands stay on the rifle, with elbows bending naturally; the gun kicks when they fire
- they flinch when hit, tilt the rifle and swap the magazine when reloading, tuck their legs when jumping, take small steps when turning on the spot, and breathe and shift weight when standing
- when killed they crumple and fall away from the shot (a headshot snaps the head back) and drop their gun

The model is in `src/assets/characterModel.ts` and the animation in `src/bots/CharacterAnimator.ts`.

In first person you see your own arms (simple box sleeves and gloves) holding each gun. They follow every bob, sway and recoil. When reloading, the gun tilts and your left hand pulls the magazine out, drops out of view for a fresh one, pushes it in and slaps it home (the shotgun instead loads shells one at a time). The pistol finishes its reload by turning side-on while your left hand racks the slide back and lets it snap forward. After each shotgun blast your left hand racks the pump back, the spent shell flies out, and the pump slides forward again. After each sniper shot your right hand works the bolt (up, back, the case flies out, forward, down); the scope comes off while you do, and goes back on by itself if you're still holding right-click. This is in `src/weapons/ViewmodelArms.ts`.

## How the bots work

Each bot has:

- **Vision**: a 120° view cone, a 60 m range, and line of sight. Bots can't see or shoot through walls.
- **Hearing**: they hear gunshots within each gun's hearing range, and they know roughly where a shot came from when they're hit.
- **Imperfect aim**: a reaction time before they start shooting, a limited turn speed, and aim that wobbles more with distance, when you move, and when they move. Their aim settles the longer they track you.
- **Navigation**: when a map loads, the game scans it for every spot a bot can stand on, on every level, and links spots a bot can walk between, including ramps and drops off ledges. Bots plan routes over this graph, so they walk around walls instead of into them. Press **B** in-game to see it.

Each bot runs a state machine (`src/bots/BotBrain.ts`). Press **B** to see each bot's state above its head:

| State       | What the bot does |
| ----------- | ----------------- |
| patrol      | Walks between random spots, pausing to look around (and grabs health if hurt) |
| investigate | Heard a gunshot or was shot by someone it can't see: turns and goes to check |
| attack      | Sees an enemy: aims, fires in bursts, strafes, keeps its distance |
| cover       | Under fire: runs to a nearby spot the enemy can't see, reloads, then peeks out |
| retreat     | Low on health: runs to health or to a hidden spot, firing back if cornered |
| chase       | Lost sight of the enemy: goes to where it was last seen |
| search      | Found nothing there: checks a few places nearby, then patrols again |

## Tweaking the game

**All the gameplay numbers are in one file: [`src/config.ts`](src/config.ts).** Each one has a comment explaining it. While `npm run dev` is running, save the file and the game reloads with the new values.

| Section          | What it controls |
| ---------------- | ---------------- |
| `CONFIG.player`  | Movement speeds, jump, gravity, crouch, health, armor, respawn time |
| `CONFIG.camera`  | Sprint zoom, head bob, screen shake strength |
| `WEAPONS`        | Each gun's damage, headshot bonus, fire rate, magazine, reload time, spread, recoil, zoom, range |
| `COMBAT`         | Aiming slowdown, crouch accuracy bonus |
| `BOTS`           | Bot speed, health, vision range and angle, memory, preferred fighting distance, names |
| `BOT_DIFFICULTY` | Easy / Normal / Hard: reaction time, aim error, turn speed, bursts, aggression, damage |
| `MATCH`          | Menu defaults, kill limits, Deathmatch time limit |
| `SURVIVAL`       | Wave growth, break between waves, health on wave clear |
| `PICKUPS`        | How much pickups give and how long they take to come back |
| `CONFIG.quality` | What Low / Medium / High graphics mean |

Examples:
- To make bots slower to react on Normal, raise `BOT_DIFFICULTY.normal.reactionTime`, for example to `0.7`.
- To make the shotgun stronger, raise `WEAPONS.shotgun.damage`.
- For longer matches, raise `MATCH.timeLimitMinutes`.

### Adding a map

Maps are plain data in [`src/map/maps/`](src/map/maps/). Each map is a list of boxes (walls, floors, crates) and ramps, with positions and sizes in meters, plus spawn points and pickup spots.

1. Copy `foundry.ts` (the arena) or `testRoom.ts` (a small room) to a new file and give it a new `id` and `name`.
2. Change the boxes, ramps, spawns, and pickups.
3. Add it to the list in `src/map/maps/index.ts`.

It appears in the match menu automatically, and bots can navigate it without any extra work.

### Swapping in real art and sound

- **Sounds**: put audio files in a `public/sounds/` folder and list them in `SAMPLE_FILES` at the top of [`src/audio/sounds.ts`](src/audio/sounds.ts), for example `shot_rifle: '/sounds/rifle.wav'`. A file replaces the generated sound with the same name.
- **Gun models**: drop `.glb` files named `pistol.glb`, `rifle.glb`, `shotgun.glb` or `sniper.glb` into [`src/assets/models/weapons/`](src/assets/models/weapons/) and they replace the built-in guns automatically (in your hands and the bots'). [`src/assets/models/README.md`](src/assets/models/README.md) explains how to export them and which named parts (sight, grips, magazine, slide, pump, bolt) make the hands and animations line up. Size and rotation fixes go in `WEAPON_MODELS` in [`src/config.ts`](src/config.ts).
- **Gun animations**: every first-person animation setting (gun position, hand positions, reload keyframes, pump/bolt/slide timing) is in [`src/weapons/animations.ts`](src/weapons/animations.ts).
- **Other models**: the character and pickup models are each made in one function in [`src/assets/`](src/assets/) (`createCharacterModel`, `createPickupModel`). Replace a function's contents to load a real 3D model instead. The comment at the top of each file explains what the rest of the game expects.
- **Textures**: wall and floor textures are drawn in [`src/assets/materials.ts`](src/assets/materials.ts). Swap in image files there.

## Troubleshooting

- **A page of text instead of the game**: that's `dev.html`, the development page. Open `index.html` instead, or use `npm run dev`.
- **The mouse isn't captured / "Click Resume"**: browsers only capture the mouse right after a click, and they refuse if you press Esc and click again very quickly. Wait a second and click **Resume**.
- **The game feels choppy**: Settings → Graphics → Medium or Low.
- **No sound**: check the volume in Settings and your Mac's volume. Browsers only allow sound after your first click in the page.
- **`npm` isn't found in Terminal**: install Node.js (see setup above), then open a new Terminal window.

## Project layout

```
src/
  config.ts       All tunable numbers
  main.ts         Starts the game (loaded by dev.html)
  core/           Game loop and screens (Game.ts), one match (Match.ts), input, settings,
                  collision, walking physics, events
  player/         Player movement and camera (PlayerController), health and armor (Player)
  bots/           Bot body (Bot), senses (Perception), aim (BotAim), state machine (BotBrain),
                  navigation (NavGraph, Navigator), spawning (BotManager), animation
                  (CharacterAnimator), debug view
  weapons/        Weapon stats/state, bullet tracing (hitscan), firing and switching
                  (WeaponSystem), the gun and arms in your hands (Viewmodel, ViewmodelArms),
                  and all their animation settings (animations.ts)
  modes/          Deathmatch and Survival rules
  pickups/        Health, armor, and ammo pickups
  map/            Map format, map builder (incl. baked lighting), 3D detail (bricks, panels,
                  crates, barriers), and maps/ (the map data)
  render/         Graphics quality, shader tweaks, and the bloom/reflection pipeline
  effects/        Tracers, sparks, bullet holes, muzzle flashes
  audio/          Sound engine and generated sound effects
  ui/             HUD, minimap, menus (title screen, main menu, setup, pause, settings,
                  end screen), the animated menu background (MenuBackdrop), styles
  assets/         Textures and models (made in code); models/ is where custom .glb files go
  entities/       Practice dummies (optional, per map)
```

## Other commands

- `npm run build`: checks the code for errors and rebuilds `index.html` and `Play.html` from the source code (run this after changing anything if you play by double-clicking or host it on a website)
- `npm run typecheck`: just checks the code for errors

Files at the top level:
- `index.html` / `Play.html`: the finished game (built, single file)
- `dev.html`: the development page that `npm run dev` uses (only works through the dev server)
